01How I work

Most of my career has been the same problem wearing different clothes: the data a business needs is scattered across an ERP, a database, system exports and a pile of spreadsheets, and somebody is rebuilding the same report by hand every month. My job is to connect those systems and make that work disappear.

Accuracy

Validation rules and reconciliation against source records before anything reaches a dashboard. A number nobody checked is not a number.

Structure

Models built to extend, not to patch. Standardised definitions so the same KPI means the same thing in every business unit.

Reliability

Automated and documented, so the solution keeps running when I am not the one running it. Adoption matters more than elegance.

ERP to BI integration pipeline

Systems integration

A U.S. manufacturer's reporting lived in three disconnected places: an Infor LX ERP on AS/400, manual Excel files and ad-hoc system exports. Finance and Sales waited on someone to assemble the numbers.

  • Extract and validate ERP data with SQL against DB2 for i, reconciled to source records before load.
  • Single semantic model in Power BI: fact tables, relationships, DAX measures and a Customer → Core → SKU drill-down.
  • Departments reach their own figures instead of filing a reporting request.

Applied AI in reporting workflows

AI implementation

Using AI in a production reporting process is less about generation and more about verification. The interesting part is deciding what you are willing to trust.

  • Generative models (GPT, Claude) applied to data preparation, documentation and summarisation inside the reporting cycle.
  • n8n for workflow orchestration across tools that do not natively talk to each other.
  • Every output validated against source data before it enters a deliverable — the step that makes it usable rather than impressive.
  • Tool selection judged against the existing stack, not against the hype.
